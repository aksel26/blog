## 사실 비교 대상은 아닙니다만

가끔 이런 궁금증이 듭니다. "reduce랑 map 중에 뭐가 더 빠를까?" 솔직히 이 둘은 근본적으로 하는 일이 달라서 직접 비교하기는 애매합니다. 하지만 굳이 얘기하자면, 일반적으로는 `map()`이 `reduce()`보다 빠른 편이에요.

왜 그런지, 그리고 실무에서 어떻게 선택해야 하는지 한번 정리해볼게요.

## map()이 빠른 이유

`map()`은 배열의 각 요소를 돌면서 변환 작업을 하는 게 전부입니다. 내부적으로는 새로운 배열을 미리 만들어두고, 각 위치에 변환된 값을 쏙쏙 넣어주는 식이에요.

```javascript
const numbers = [1, 2, 3, 4, 5];
const doubled = numbers.map((x) => x * 2);
// [2, 4, 6, 8, 10]
```

이 과정이 꽤 잘 최적화되어 있어요. 각 요소의 변환이 독립적이라서 이론적으로는 병렬 처리도 가능하고, 자바스크립트 엔진 입장에서도 예측 가능한 패턴이라 최적화하기 쉽습니다.

## reduce()는 왜 좀 느릴까?

`reduce()`는 조금 다릅니다. 누적값(accumulator)을 계속 업데이트하면서 진행하잖아요? 이게 핵심인데, 이전 단계의 결과가 다음 단계에 영향을 주는 **순차적 의존성**이 생깁니다.

```javascript
const numbers = [1, 2, 3, 4, 5];
const sum = numbers.reduce((acc, curr) => acc + curr, 0);
// 15
```

각 반복마다 이전 상태를 참조해야 하니까 `map()`처럼 단순하게 최적화하기가 어려워요. 병렬 처리도 불가능하고요. 이런 이유로 일반적으로 `reduce()`가 `map()`보다 느린 편입니다.

## 그럼 언제 뭘 써야 할까?

성능 차이를 떠나서, 각자의 용도가 명확해요.

### map()을 써야 할 때

배열은 배열인데 각 요소만 바꾸고 싶을 때 씁니다.

```javascript
// 숫자를 문자열로 변환
const strings = [1, 2, 3].map((n) => n.toString());

// 객체 배열에서 특정 속성만 뽑기
const names = users.map((user) => user.name);
```

배열의 길이는 그대로고, 각 요소만 변환되죠.

### reduce()를 써야 할 때

배열을 완전히 다른 형태로 바꾸거나 하나의 값으로 합칠 때 씁니다.

```javascript
// 배열 합산
const total = prices.reduce((sum, price) => sum + price, 0);

// 배열을 객체로 변환
const userMap = users.reduce((map, user) => {
  map[user.id] = user;
  return map;
}, {});

// 조건부 집계
const adultCount = people.reduce((count, person) => {
  return person.age >= 18 ? count + 1 : count;
}, 0);
```

보시다시피 배열을 숫자 하나로 줄이거나, 객체로 바꾸거나, 복잡한 로직을 돌릴 때 유용해요.

## 실무에서는 어떻게?

사실 대부분의 경우 성능 차이는 체감하기 어렵습니다. 몇십만 개의 데이터를 처리하는 게 아닌 이상, 가독성과 유지보수성이 훨씬 중요하거든요.

제가 실무에서 지키는 원칙은 간단해요.

- **명확한 변환이 목적이면 map()**
- **복잡한 집계나 형태 변환이 필요하면 reduce()**

억지로 `reduce()`로 `map()` 흉내 내는 코드는 읽기도 어렵고 의도도 불명확해요. 반대도 마찬가지고요.

```javascript
// ❌ reduce로 map 흉내내기 (비추천)
const doubled = numbers.reduce((arr, n) => {
  arr.push(n * 2);
  return arr;
}, []);

// ✅ 그냥 map 쓰기
const doubled = numbers.map((n) => n * 2);
```

성능을 위해 억지로 메서드를 바꾸는 것보다, 코드의 의도를 명확하게 드러내는 게 장기적으로 더 이득입니다. 정말 성능이 문제라면 그때 가서 프로파일링하고 최적화해도 늦지 않아요.

## 마무리

`map()`이 일반적으로 빠르긴 하지만, 둘은 애초에 다른 목적을 가진 도구입니다. 망치가 필요할 때 드라이버를 쓸 수 없듯이, 상황에 맞는 메서드를 선택하는 게 가장 중요해요.

고민될 때는 이렇게 생각하면 됩니다. "배열을 배열로 바꾸나? 다른 형태로 바꾸나?" 전자면 `map()`, 후자면 `reduce()`입니다.
