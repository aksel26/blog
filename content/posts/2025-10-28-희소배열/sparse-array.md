희소 배열의 `length`가 100이라고 해서 100개의 메모리 공간을 미리 확보할까?

**아니다.** JavaScript는 희소 배열을 위해 메모리를 미리 확보하지 않는다.

## JavaScript 배열의 비밀: 사실은 '객체'다

이것이 모든 것의 해답이다.

### 전통적인 배열 (C, Java 등)

- 사용자가 `int[100]` (100칸짜리 정수 배열)을 선언하면, 컴퓨터는 **연속된 메모리 공간 100개**를 통째로 예약한다
- 각 칸은 비어있더라도 (0으로 채워져 있더라도) 실제 물리적인 공간을 차지한다
- `arr[50]`에 접근하는 것은 '시작 주소 + (50 × 한 칸의 크기)'로 매우 빠르다

### JavaScript의 배열

JavaScript의 배열은 사실 **'키(key)가 숫자인 특수한 객체(Object)'**에 가깝다.

`let arr = []`를 선언하고 `arr[0] = 'a'`와 `arr[99] = 'b'`를 넣는 것은, 내부적으로 이런 객체를 만드는 것과 비슷하다.

```javascript
// JavaScript 엔진이 '희소 배열'을 인식하는 방식 (개념적으로)
let sparseArrayStorage = {
  0: "a", // 0번 키에 'a' 저장
  99: "b", // 99번 키에 'b' 저장
  length: 100, // 'length'라는 속성을 따로 관리
};
```

## 메모리 할당 방식: "필요한 만큼만"

- 위 예시에서 JavaScript 엔진은 **'a'를 저장할 공간 1개**와 **'b'를 저장할 공간 1개**만 할당한다
- 그리고 `length`라는 속성값(100)을 저장할 약간의 공간을 추가로 사용한다
- **중간에 비어있는 1번부터 98번까지의 공간은 아예 존재하지도, 할당되지도 않는다**
- 이것이 JavaScript에서 희소 배열이 메모리 효율적인 이유다

## 'length'의 정체

희소 배열에서 `length` 속성은 **"실제 데이터의 개수"가 아니다.**

`length`는 그저 **"배열에 설정된 가장 큰 숫자 인덱스 + 1"** 값을 기억하는 **별도의 속성(Property)**일 뿐이다.

엔진은 `arr[99]`에 값을 넣는 순간, "아, 가장 큰 인덱스가 99구나. 그럼 `length` 속성 값은 100으로 업데이트해야겠다"라고 판단한다.

```javascript
const arr = [];
arr[0] = "first";
arr[99] = "last";

console.log(arr.length); // 100
console.log(arr[50]); // undefined (존재하지 않음)
console.log(Object.keys(arr)); // ['0', '99'] - 실제로는 2개만 존재
```

## 밀집 배열 vs 희소 배열

### 밀집 배열 (Dense Array)

JavaScript 엔진이 최적화를 위해 C언어처럼 **연속된 메모리**에 저장하려고 시도한다. 빠른 접근을 위해서다.

```javascript
const dense = [1, 2, 3, 4, 5];
// 엔진은 이걸 연속된 메모리에 저장하려고 함
```

### 희소 배열 (Sparse Array)

사용자가 인덱스를 띄엄띄엄 사용한 순간, 엔진은 "아, 이건 밀집 배열이 아니네"라며 **객체(딕셔너리 또는 해시맵) 방식**으로 전환한다.

```javascript
const sparse = [];
sparse[0] = "a";
sparse[1000] = "b";
// 엔진은 이걸 객체처럼 관리함
// 메모리는 2개의 값 + length 속성만 사용
```

## 정리

- **밀집 배열**: 연속된 메모리 할당, 빠른 접근 속도
- **희소 배열**: 객체 방식으로 관리, 메모리 효율적
- **핵심**: `length`가 100만이어도 실제 값이 2개뿐이라면, 메모리는 **딱 2개의 값과 `length` 속성(및 약간의 관리 정보)**을 저장할 만큼만 사용한다. 100만 개의 공간을 절대 차지하지 않는다.

이것이 JavaScript 배열이 다른 언어의 배열과 다른 점이자, 유연성을 제공하는 이유다.
